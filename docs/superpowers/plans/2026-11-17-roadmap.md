# RaaGamaalika — Build Roadmap

Spec: `docs/superpowers/specs/2026-11-17-raga-recognizer-design.md` (approved 2026-11-17)

The spec covers six subsystems, so it is built as a sequence of plans.
- Each plan ends with working, testable software.
- Each plan is written only when its turn comes, so it can use what the
  previous one taught us (real accuracy numbers, cold-start times, the
  pitch tool chosen).

| # | Plan | Delivers | Spec sections | Status |
|---|------|----------|---------------|--------|
| 1 | **Engine v0 + public web app (local)** | Recognition with model v0 (theory matcher, shruti check, hand-crafted fingerprints, seed examples from Saraga), the public API, the PWA (listen/upload/YouTube, result, raga detail, history, about), Docker image, CI tests, and the v0 evaluation and calibration report | 5.1, 5.2, 5.3, 5.4 (public), 5.5 (public), 7 (baseline) | Written: `2026-11-17-plan-1-engine-v0-and-web-app.md` |
| 2 | **GCP deploy** | Cloud Storage-backed `ExampleStore`, manifest sync between instances, Secret Manager, the Cloud Shell setup script plus `docs/deploy.md` (owner runs it), and GitHub Actions deploying to Cloud Run with Workload Identity Federation. Ends with a smoke-tested public URL. | 3, 5.6 | Next |
| 3 | **Admin: teaching ragas** | Admin login, adding examples (record/upload/YouTube), "Save as example", the swara-mismatch and shruti warnings on save, coverage view with graduation progress, raga editor, and re-extract all | 5.4 (admin), 5.5 (admin), 5.7 | — |
| 4 | **Training** | The two-headed model, tuned theory and combination parameters, the Cloud Run training job, the promotion gate, the training screen, rollback, and the graduation rule. Produces v1. | 5.9, 7 | — |
| 5 | **Kritis** | Kriti catalog seed, kriti search, kritis on results and raga pages, YouTube links, and the admin kriti editor | 5.8 | — |
| 6 | **Phase 2: full-concert timeline** | Segmentation of long recordings into items with ragas | 2 (Phase 2) | Not before 1–5 are in use |

Order rationale: Plan 1 gives something usable locally right away. Plan 2
puts it online before the admin and training work, so later plans are
tested in the real environment. Plans 3 and 4 depend on persistent
storage. Plan 5 is independent and could move earlier if wanted.
